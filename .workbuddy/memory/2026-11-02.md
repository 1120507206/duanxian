## 语音播报（封板事件流）上游连接方式切换：裸 WS → Socket.IO

- 背景：旧站（`D:\code\duanxianxai-vue3\new-vue3`）播报已切到 dxx-ws-v2；协议文档 https://t.duanxianxia.com/ws-doc.html
  - 地址 `https://t.duanxianxia.com`，`path: '/dxx'`（是 path 参数，不能拼进 URL）
  - 封板频道 namespace `/ztlive`，事件名 `zt`；只允许 `transports: ['websocket']`，无鉴权
  - 报文 `from` 仍为 `ztpool`，字段与旧 wss3 一致（实测无 `audio` 字段，只有 `readurl`）
- 本项目改动（前端零改动 —— 前端只连自家 `/api/ztlive/stream` SSE）：
  - `backend/src/services/ztliveSocketService.js` 重写连接层：`Manager` + `manager.socket('/ztlive')` + `on('zt')`；删掉手写 `ping` 心跳与主备域名切换（交给 Socket.IO 自带重连/心跳）；publish / 环形缓冲 / SSE 总线 / 状态接口全部保持不变
  - `backend/src/config/index.js`：新增 `ztliveWsPath` / `ztliveWsNamespace` / `ztliveWsEvent` / `ztliveWsCaFile`，删除 `ztliveWsFallbackUrl`
  - `backend/.env.example` 同步更新
  - `backend/package.json` + `package-lock.json` 新增 `socket.io-client@4.8.4`（部署走 `npm ci --omit=dev`，lock 必须同步）
- **关键坑：TLS 证书链**。`t.duanxianxia.com` 握手只下发站点证书、不带中间证书（Certum DV TLS G2 R39 CA），Node 不会像浏览器那样按 AIA 自动补齐，默认直接报 `unable to verify the first certificate`。
  - 解决：把中间证书存到 `backend/certs/intermediate.pem`，连接时 `ca: [...tls.rootCertificates, 读文件]`，不放宽校验。部署必须带上这个文件，上游换证可用 `ZTLIVE_WS_CA_FILE` 覆盖。
- 验证：`ztlive_ws_open url=https://t.duanxianxia.com/ztlive`；实测收到封板事件并经 SSE 转发（`event: ztpool` + `row.code=301326`）；`/api/ztlive/stream/status` 显示 `ztpoolEvents` 递增。旧 wss3 当时仍可用（双通道并行期）。
- 备注：`deliverables/涨停播报-WebSocket接入可行性分析.md`、`TDX_STANDALONE.md` 里仍是 wss3 时代的描述，属历史文档，未改。

## 第二批 P1 优化（已落地）

1. **首屏拆分：落地页不再加载 Element Plus**
   - `main.js` 去掉 EP 全量安装；新增 `plugins/element.js`，由 `router.beforeEach` 在进入非 landing 路由时 `await ensureElementPlus()`（动态 import EP + 中文 locale + 整包 CSS + 图标白名单）。
   - `App.vue` 的 `AppLayout` 改为 `defineAsyncComponent`，否则它 import 的 EP 会重新进入首屏图。
   - `Landing.vue` 去掉 `ElMessage` 与 `el-icon`：自写 20 行 toast + 原生 span 包 Sunny/Moon。
   - `plugins/icons.js` 只导出模板/菜单真正用到的 20 多个图标；`Search` 因是 HTML 保留标签改注册为 `SearchIcon`（同步改 6 个模板）。
   - **关键坑**：Vite 8 底层 Rolldown，`manualChunks` 在 `codeSplitting` 开启时被忽略；必须用 `build.rollupOptions.output.codeSplitting.groups`。另外 Vue 运行时若不单独分组会被并进 `element-plus` chunk，导致所有页面静态依赖 EP、首屏又预加载 1.1MB。最终分组：icons(40) > vue-vendor(30) > element-plus(20，含 @vueuse) > echarts(10)。
   - 结果：`dist/index.html` 只预加载 runtime + icons(97K) + vue-vendor(45K) + main(50K) + CSS；浏览器实测落地页总传输约 **152KB**（原 ~1.5MB JS + 348KB CSS）。
   - 独立页仍全量 EP（试过按需注册 13 个组件，chunk 仍 863KB，无收益，已回退），只把图标从全量改为 `SearchIcon`。

2. **播报表格减少重渲染** `useZtliveFeed.js`
   - 快照与上一轮按 `code` 做**顺序无关**比对（17 个展示字段），内容没变就完全不替换 `payload`，不触发 150~800 行 × 14 列的全表 vnode 重建。
   - `mergeWithPending` 复用上一轮行对象（`Object.assign` 原地更新），高亮计时器和 Vue 渲染缓存都不丢。
   - pending 行只在「尚未被快照收录」时排除比对；一旦收录就参与，避免推送后 2 分钟内每轮都误判为变化。

3. **权益缓存** `accountService.getEntitlements`
   - 15 秒 TTL，key 为 token 或 deviceId，容量 2000；`grantMembership` / `revokeSession` / `revokeAllSessions` / `setAccountStatus` 主动 `invalidateEntitlementCache()`，付款后下一轮询即解锁。
   - 实测 `/api/ztlive` 第二次请求 4.5ms（首次 94ms）。

4. **SSE 广播** `ztliveStreamService.js`
   - 事件只 `JSON.stringify` 一次，所有客户端复用同一 chunk；断线补发仍逐条序列化（低频）。
   - `res.writableLength > 1MB` 判定慢客户端，直接 destroy + cleanup，防写缓冲吃内存。

5. **Nginx** `deploy/nginx/duanxian.conf`
   - 新增 `upstream duanxian_api` + `keepalive 32`，`/api/` 加 `Connection ""`、读超时 60s。
   - 新增 `location = /api/ztlive/stream`：`proxy_buffering off`、读/写超时 3600s、`access_log off`（token 还在 query 里，先避免落日志）。

6. **测试/验证**
   - 新增 `tests/backend/entitlementCache.test.js`（缓存命中、grant 失效、revoke 失效）；`npm test` 38/38，lint 0 error，build 通过。
   - 用 Playwright（系统 Edge）实测：落地页仅加载 vue-vendor + icons，无 EP；`/ztlive` 与 `/ztlive.html` 均渲染 149~150 行、首行名称正确、无 console warning/error。
   - 注意：headless 截图里 `el-table` 固定列会出现「重影」，但 DOM 检查（行数、首行文本、header/body 位置）完全正常，判断为无头合成伪影，不是真实布局问题。
