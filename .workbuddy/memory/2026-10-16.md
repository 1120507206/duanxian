## 运营后台 /admin（已完成，40/40 E2E 通过）

用户要求：把 `npm run member ...` 那套 CLI 运维做成浏览器后台 —— 能看谁注册了、谁充值了，并且 guser/rebind/void/passwd/phone 这些能力全都要有。

### 架构决定
- 后台做进现有 SPA（`/admin/*`，懒加载分包），**不单独起一个项目**：Nginx 的 `try_files` 已兜到 index.html，部署零改动；普通用户访问站点不会下载后台代码（已验证主包不含后台文案）。
- **管理员账号没有默认口令**，只能 `npm run admin init` 从服务器创建。登录页检测到未初始化会显示这条命令，而不是暗示 admin/admin。
- 独立三表：`admin_users` / `admin_sessions`（12 小时 TTL，远短于前台 30 天）/ `admin_logs`（**只读，无任何删除接口**）。
- 后台 token 走 `X-Admin-Token` 头，不复用 `X-Session-Token`：用户会话永远换不来后台权限。
- 每个写操作都 `logAction`；`ACTION_LABELS` 同时喂 CLI 与后台页面，文案不漂移。

### 文件清单
后端：`services/adminService.js`（鉴权+审计+限流）、`services/adminQuery.js`（读模型：概览/用户/订单/激活码）、`routes/admin.js`（每条路由对应一条 CLI 命令）、`middleware/admin.js`、`scripts/admin.js`（`npm run admin init|list|disable|enable|logs`）。
前端：`api/admin.js`（独立 axios 实例，不共用前台那个——鉴权头不同且不该弹全局 toast）、`stores/admin.js`、`utils/adminToken.js`（键 `duanxian:adminToken`，刻意与前台 `duanxian:token` 分开）、`utils/adminFormat.js`、`views/admin/Admin{Login,Layout,Overview,Users,Orders,Codes,Logs}.vue`。

### E2E 抓到的真实缺陷（值得记住的一类）
`App.vue` 把除落地页外的所有路由都套进 `AppLayout`，导致 **`/admin` 也被套**：后台登录页顶着站点侧边栏，且首访的「风险提示」弹窗整页盖住登录表单，按钮点不到（Playwright 报 elementFromPoint = `DIV.el-overlay-dialog`）。修复：App.vue 用 `route.path.startsWith('/admin')` 判定独立页。教训：**新增独立壳层路由时，App.vue 的布局分发必须同步改**。

### 运营口径（写死在实现里，别改错）
- 后台赠送会员与用户续费同语义：**从原到期日叠加**，不是从今天重算。
- 激活码「作废」只允许 unused；已使用的码作废 = 收回已付款权益，属于退款流程，不能顺手做。
- `rebind` 只对「未登录时兑换到设备」的码有意义；核销到账号的码直接拒绝并提示用户重新登录（权益跟人走）。
- 后台接口返回**完整手机号**（前台 /api/auth/* 是脱敏的）——运营要靠它核对付款人。

### 测试数据已全部清零（账户 0 / 订单 0 / 激活码 0 / 管理员 0）
测试管理员删掉了——留一个已知密码的管理员等于留后门。用户首次使用需自己跑 `npm run admin init`。

## 注册改为「手机号 + 密码」，验证码默认关闭（已完成，20/20 E2E 通过）

用户要求：注册不再发短信验证码，只要密码即可。

### 实现方式：一个开关驱动前后端，而不是删代码
- `accountService.js` 新增 `AUTH_POLICY`（`requireSmsCode`，环境变量 `REQUIRE_SMS_CODE`，默认 false），通过 `/api/auth/config` 下发 `requireSms/passwordMin/passwordMax/smsReady`。
- 前端 `Login.vue` 按下发的开关渲染表单：requireSms=false → 无验证码输入框、密码必填 + 确认密码、登录页只有密码登录 + 「忘记密码」提示；=1 → 自动长回验证码表单。**前端不得硬编码注册方式**。
- 密码成为唯一凭据 → 注册必填（8–32 位）；`/sms/send` 与 `/login/code` 在关闭状态下返回明确提示，不白烧短信费。
- 新增 `member.js passwd --phone --password` 人工重置密码（无短信 = 无自助找回；走 CLI 不开放 HTTP，避免成为撞库入口）；`accountService.resetPasswordByPhone`。
- 防薅新人礼闸门调整：设备 2 个/7 天（主力），IP **放宽到 20 个/24 小时** —— 小区宽带/公司网络/4G 运营商 NAT 下大量真实用户共享出口 IP，IP 闸太紧会把引流来的真实用户挡在新人礼外（调试时 5 个就触发了，实测确认过这个风险是真实的）。

### 已知代价（写给未来的自己）
- 手机号**未经验证**，只是用户名：可被任意占用（含别人的号码）、无自助找回密码。
- 出现「手机号被占」客诉或人工重置吃不消时，就是该设 `REQUIRE_SMS_CODE=1` 的信号。

### E2E 踩坑记录（下次写测试直接避开）

### 关键设计取舍
- 权益挂**账户**而非设备：这是手机号注册的根本目的，否则登录体系没有意义。
- 设备体系保留：用于匿名渠道归因、埋点、首访建档；注册时把当前设备关联到账户，归因链不断。
- 收款码无回调必须人工核销：在 `payment_orders` 里走 `pending → confirming → paid/rejected` 状态机，
  默认 `PAY_AUTO_APPROVE=0`（安全第一），上线前不可改为 1。
- 金额尾数（0.01–0.09）：个人码对账的唯一锚点，必须在 UI 上向用户解释清楚。
- 短信通道 pluggable：用 console 驱动本地能跑通；真实上线必须接腾讯云 SMS 或 webhook 中转。

- **推荐商业模式**：Freemium 订阅（免费看表 / 付费出声）+ 渠道分成 30–40% 首年。
- **冷启动只投 3 渠道**：通达信插件生态（最高优先级）、淘股吧+股吧、公众号（可复用旧站存量粉丝）。
