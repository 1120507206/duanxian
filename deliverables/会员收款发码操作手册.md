# 会员收款与账户体系操作手册

> 配套代码：
> - 后端：`backend/src/services/accountService.js`、`payService.js`、`smsService.js`；`backend/src/scripts/member.js`
> - 前端：`/login`（注册/登录）、语音开关旁的「语音会员」锁（付费墙）、`/activate`（激活码兑换）
> - 静态资源：`frontend/public/pay/`
>
> 本手册按「无营业执照」的现状编写，拿到执照后的升级路径见文末。

---

## 一、现在的收钱链路长什么样

用户路径被大幅缩短了：

1. **未登录**打开涨停播报 → 点语音开关 → 弹窗说「注册即送 30 天」
2. 跳 `/login` 注册 → **自动送 30 天会员** → 回到页面语音已解锁
3. 30 天后到期 → 再点语音 → 弹收款码 → 用户扫码付款 → 点「我已付款」
4. 你在后台核对账单 → CLI 一键核销 → 会员时长在账户上叠加

会员权益挂在**账号**上，所以换电脑、清浏览器、重装通达信都不会丢会员。
激活码体系仍然保留，主要给 **渠道博主 / 线下分销 / 活动赠送** 用。

## 二、上线前要做的事（现在只剩一件是必须的）

### 1. 短信验证码通道（当前不需要，可选）

**当前注册方式是「手机号 + 密码」，不发验证码**，所以这一步现在可以跳过。
短信通道被一个开关整体关闭：后端 `AUTH_POLICY.requireSmsCode`（环境变量 `REQUIRE_SMS_CODE`，默认关闭）。
关闭状态下 `/api/auth/sms/send` 与验证码登录会直接返回提示，不会白烧短信费。

什么时候需要重新打开：你需要「证明手机号真的属于用户」的时候 —— 自助找回密码、
改绑手机、防止有人拿别人的号码注册。打开方式：

```bash
# backend/.env
REQUIRE_SMS_CODE=1
SMS_DRIVER=tencent        # 或 webhook
TENCENT_SMS_SECRET_ID=AKIDxxx
TENCENT_SMS_SECRET_KEY=xxx
TENCENT_SMS_SDK_APP_ID=1400xxx
TENCENT_SMS_SIGN_NAME=你的签名
TENCENT_SMS_TEMPLATE_ID=198xxxx
```

打开后**前端注册表单会自动长出验证码输入框、登录页自动出现「验证码登录」**，
不需要改任何前端代码 —— 表单形态由 `/api/auth/config` 下发的 `requireSms` 决定。

| 通道 | 要填的环境变量 | 适用场景 |
|---|---|---|
| **腾讯云 SMS** | 上表 5 个变量 | 有腾讯云短信服务 |
| **Webhook 中转** | `SMS_WEBHOOK_URL` / `SMS_WEBHOOK_TOKEN` | 用阿里云/华为云/自建网关/短信转发器 |

> 短信签名报备需要 1–3 个工作日，常需要营业执照或个体户。
> 现在用「手机号 + 密码」注册不依赖任何资质，这也是当初关掉它的原因。

### 2. 把收款码图片放到 `frontend/public/pay/`

```
public/pay/wx.png      ← 微信个人收款码
public/pay/alipay.png  ← 支付宝个人收款码
```

也可以不改仓库，在 `backend/.env` 里直接填图床地址：

```bash
PAY_WX_QR_URL=https://你的图床/wx.png
PAY_ALIPAY_QR_URL=https://你的图床/alipay.png
PAY_CONTACT=你的微信号/公众号名   # 会显示在收银台底部
```

**注意**：个人收款码没有支付回调，用户点「我已付款」之后必须你人工核对账单再开通。
这是过渡方案；拿到执照后应尽快切微信/支付宝商户号。

### 3. 复核 `.gitignore`

`codes.txt`、所有 `codes*.txt`、`backend/*.db`、`.env` 都已经在 `.gitignore` 里。
**不要把真实的收款码或短信密钥提交到 git**。

## 三、注册规则（手机号 + 密码，送 30 天）

注册接口：`POST /api/auth/register`

- **手机号 + 密码即可注册**，不发验证码（`REQUIRE_SMS_CODE=1` 时才要求验证码，且密码变选填）
- 密码**必填**（8–32 位）—— 没有短信就没有第二个凭据，注册页会要求输两遍防手误
- 注册成功后自动获得 `TRIAL_DAYS = 30` 天会员（`trial` 套餐）
- 防薅新人礼的两道闸：
  - **设备**：同一浏览器 7 天内注册的第 3 个号起不给试用（正常用户碰不到）
  - **IP**：同一出口 IP 24 小时内第 21 个号起不给试用。**这个数故意设得很宽** ——
    小区宽带、公司网络、4G/5G 的运营商 NAT 下大量真实用户共享一个 IP，
    闸门太紧会把花钱引来的真实用户挡在新人礼外面，损失比被薅几个试用期大
- **手机号未经验证**：它现在只是个用户名，不代表号主本人。任何人可以用任意 11 位号码注册
  （包括别人的号码）。这带来的两个直接后果：
  1. **没有自助找回密码** —— 用户忘记密码时，只能你人工重置（见下节 `passwd` 命令）
  2. 出现「手机号被别人占用了」的客诉时，用 `passwd` 也救不了 —— 那个号被别人注册了，
     只能人工清理数据或引导用户换号。这类问题多了，就是该打开短信验证的信号

如果你想改新人礼天数，只改后端 `backend/src/services/accountService.js` 里的
`TRIAL_DAYS` 常量即可，前后端其它地方都会同步。

## 四、收款码支付后的核销流程

### 用户侧

1. 到期后点语音开关 → 弹窗内点「立即开通会员」
2. 选套餐（月/季/年）和支付方式（微信/支付宝）
3. 页面生成订单，显示**精确金额**（例如 ¥268.08，角分尾数是订单标识）
4. 用户扫码付款，尽量在备注里填订单号（支付宝支持；微信个人码不支持备注）
5. 用户点「我已完成付款」，填写昵称/备注

### 你侧（每天花 2 分钟）

```bash
cd backend

# 看有哪些人点了「我已付款」，等你核对
npm run member orders

# 输出示例：
# DX202610165648  ¥268.08  year     wx      138****5460  2026/10/16 10:57:32
#     付款备注：微信昵称 测试

# 打开你的微信/支付宝账单，确认收到这笔 ¥268.08（或对应尾数）后，执行核销
npm run member approve --order DX202610165648

# 如果核对后发现没到账 / 金额对不上
npm run member reject --order DX202610165648 --reason "未收到该笔款项"
```

- 核销成功后，该账号的会员时长会**在原到期日基础上叠加**（续费不会吃掉剩余天数）。
- 订单号是幂等的：重复 approve 会提示「该订单已核销过」，不会重复加时长。

### 快捷查某个用户

```bash
npm run member phone --phone 13812345678
```

会输出：账户状态、会员剩余天数、订单列表、是否已领新人礼、是否设置了密码。

## 五、激活码体系（给渠道 / 分销 / 活动用）

激活码现在**充到账户**上，不再只绑设备。用户登录后兑换，换设备也不丢。
未登录时兑换则回落到设备（兼容早期场景）。

### 生成激活码

```bash
cd backend
npm run member gen --plan year --count 50 --channel tdx-blogger-a
```

- `--channel` 标记这批码卖给哪个渠道，后续结算分成全靠它。
- `--plan` 可选 `month` / `quarter` / `year`。

### 导出纯码

```bash
npm run member export --status unused --plan year --channel tdx-blogger-a > codes.txt
```

- **文件落点**：`backend/codes.txt`（必须在 `backend` 目录下执行 `>` 重定向）。
- 每行一个码，直接复制发给渠道或用户。
- 已加入 `.gitignore`，**不要提交到 git**。

### 用户兑换

- 站内弹窗：涨停播报页 → 点「语音会员」→ 输入激活码
- 独立页：`https://你的域名/activate`

### 渠道分成结算

按 `channel` 统计：

```bash
npm run member stats
```

会显示「渠道分布」，按渠道名聚合设备数和付费订单，据此给渠道结账。

## 六、每天看一眼的数

```bash
npm run member stats
```

| 指标 | 含义 | 健康线 |
|---|---|---|
| 注册转化率 | 注册数 ÷ 设备数 | 起步 5–15% |
| 付费转化率 | 历史开通过会员 ÷ 注册数 | 工具类 3–8% |
| 待核对订单数 | 点了「我已付款」等你核销 | 盘中应 ≤ 10 笔，收盘前清掉 |
| `voice_on` 事件数 | 真有人开着语音盯盘 | 核心北极星指标 |
| `pay_click` → `order_create` | 点了开通到下单 | 差值大 = 支付流程卡 |

## 七、运营后台（浏览器里干完所有日常操作）

上面的 CLI 命令现在都有了图形界面，地址是 **`https://你的域名/admin`**（本地开发是 `http://localhost:3000/admin`）。

### 7.1 首次开通（必须做一次）

出于安全考虑，**代码里没有默认管理员账号**——后台能重置任意用户密码、能改任意人的会员时长，如果它能在浏览器里自举，任何先到的人都能抢注管理员。所以第一把钥匙必须从服务器上造：

```bash
cd backend
npm run admin init --username admin --password 你的密码
```

- 同名账号再执行一次 = **重置密码**（忘掉后台密码时的唯一恢复路径），重置会立刻踢掉该管理员的全部在线会话
- 其他命令：`npm run admin list`（看有哪些管理员）、`npm run admin disable --username xxx`（停用）、`npm run admin logs`（在终端看操作日志）

### 7.2 后台能做什么

| 页面 | 对应的 CLI | 用途 |
|---|---|---|
| **运营概览** | `stats` | 注册数、有效会员、累计收入、待核对订单、注册/付费趋势图、渠道来源、系统告警 |
| **用户管理** | `phone` / `guser` / `passwd` | 搜索用户、看会员状态与消费、**赠送会员**（补偿/送朋友）、**重置密码**、停用/启用、看详情（订单/设备/激活码/登录记录/行为） |
| **订单管理** | `orders` / `approve` / `reject` | 按状态筛选订单，**核销开通**（有二次确认，提示先对账单）、拒绝并记原因 |
| **激活码** | `gen` / `export` / `list` / `void` / `rebind` | 生成、导出/复制纯码、作废、把已用码迁移到新设备 |
| **操作日志** | `admin logs` | 谁、什么时候、对谁、做了什么、从哪个 IP |

### 7.3 必须知道的三件事

1. **所有写操作都落审计日志**，且日志**只读、任何人删不掉**（连后台自己也没有删除接口）。出纠纷时它是唯一的凭据。
2. **核销订单前先对账单**。界面会展示金额与尾数（同一套餐多笔订单金额一样，尾数是唯一区分手段），微信个人码不能填备注、支付宝可以，对账方式不同。
3. **迁移激活码**只对「未登录时在设备上兑换」的老路径有意义。现在用户登录状态下兑换的码是核销到**账号**上的，权益跟着人走——换设备重新登录就行，不需要也不允许迁移（界面会直接提示）。

### 7.4 安全建议

- 后台会话 12 小时自动过期；连续 5 次输错密码锁 15 分钟。
- 建议在 Nginx 里给 `/admin` 加一层 IP 白名单，或至少不要把它写进任何对外宣传物料。
- 如果有多人运营，用 `npm run admin init` 给每个人建独立账号，别共用 —— 审计日志才有意义。

### 7.5 不想用后台，CLI 依然全部可用

```bash
# 手动给某个账户送 30 天（补偿 / 赠送给朋友）
npm run member guser --phone 13812345678 --days 30

# 手动给某个账户开一年
npm run member guser --phone 13812345678 --plan year

# 用户换设备后，把已用激活码迁移到新设备
npm run member rebind --code DXY-XXXX-XXXX --device <新设备标识>

# 作废一个激活码
npm run member void --code DXY-XXXX-XXXX

# 用户忘记密码（当前注册不发验证码，没有自助找回，只能人工重置）
npm run member passwd --phone 13812345678 --password 新密码abc123
# 执行后该账号所有登录态立即失效，用户用新密码重新登录即可

# 确认某个用户的状态
npm run member phone --phone 13812345678
```

后台和 CLI 走的是**同一批 service 函数**，不存在"后台改了 A、命令行改了 B"的偏差。服务器连不上数据库客户端、或后台出问题时，CLI 是兜底手段。

## 八、拿到营业执照之后（升级路径）

1. 申请**微信支付商户号**（Native 扫码支付最适合网页工具）。
2. 后端加自动支付回调：用户扫码付款后，微信/支付宝主动通知服务端，服务端自动核销。
3. 自动核销开启后，可以把 `PAY_AUTO_APPROVE=1` 打开，用户付款后秒开通，零人工。
4. 个人收款码方案下线，激活码体系保留给渠道分销用。
5. 费率从「个人码免费但人工成本」降到约 0.6%。
6. **同步打开短信验证码**（`REQUIRE_SMS_CODE=1`）：有了商户号通常也有执照，
   签名报备不再是障碍；而自助找回密码这件事，用户量过百之后人工重置会吃不消。

## 九、合规红线（每次写推广文案前读一遍）

我们是**行情数据展示工具**，不是证券投资咨询。这条边界决定了项目能不能长期做。

**绝对不做**：
- 任何个股买卖建议、点位、仓位建议
- 付费群里的「带单」「抄作业」「明日标的」
- 收益承诺、晒盈利截图、暗示跟买
- 代客理财、收益分成、诱导开户入金
- 宣传语出现「预测涨停」「稳赚」「必涨」「翻倍」

**监管依据**：《证券法》第 120/160 条要求证券投资咨询业务持牌经营；
2025 年 10 月北京朝阳法院已判无资质荐股者**非法经营罪**（2 年 6 个月 + 罚金 1500 万）；
2025 年 12 月中央网信办将无资质荐股纳入网络名人账号负面清单。

**产品里已经做好的防线**：`/about` 风险说明页、首访风险提示弹窗、
所有营销文案只描述工具能力、登录页/付费墙底部都带「不构成投资建议」声明。
